# Requests

The assignments that principals submitted in the client portal. A request only becomes a file once the office accepts it.

## Opening the screen

Click **Requests** in the menu on the left. If requests are waiting, the home screen shows how many.

## The list

- By default you only see the requests awaiting a decision. Tick **Also accepted or declined** for the rest.
- Double-click a row to open the request.

## Request

On the left is what the principal filled in: who submitted the request, the survey type, the vessel, the port and terminal, the requested date, the reference, the description and the attachments (for example the letter of instruction or the stowage plan).

- **Accept**: choose the office, the vessel, the surveyor, the time and the report language. For the vessel, Quaymark suggests an existing vessel if the IMO number, ENI number or name matches; otherwise a new vessel from the request's details. The requested time is already filled in. Quaymark then creates the file, copies the attachments to the **Documents** tab and sends the principal an email.
- If the office works with this vessel for another principal, and this principal is a party there, a warning appears above **Accept**. → [Conflicts of interest](dossiers.md#conflicts-of-interest)
- **Decline** asks for a reason. The principal sees it in the portal and in the email.
- Deciding requires the right to edit files. A request is decided only once: if two colleagues click at the same time, the second is told it has already been decided.

## Notifications to the principal

The principal's portal users receive an email when their request is accepted or declined, when a file is scheduled or moved, and when a report, letter, certificate or invoice is issued. The email has no attachment, only a link to the portal. You turn it off per relation on the Client portal tab; each user can also turn it off. Every notification sent appears in the file's journal.
